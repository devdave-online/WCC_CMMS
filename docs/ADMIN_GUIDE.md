# WCC Admin Guide

This guide is for supervisors, managers, and administrators responsible for configuring and maintaining the WCC system.

## Initial Setup

### Creating the First Admin User

If no users exist yet:

1. Use a database tool (phpMyAdmin or mysql command line) to insert a user directly:

```sql
INSERT INTO users (username, password_hash, role_level, status)
VALUES ('admin', '$2y$10$...', 4, 'active');
```

Replace the password hash with one generated by `password_hash('yourpassword', PASSWORD_DEFAULT)` in PHP.

Alternatively, use one of the setup/seed scripts in the project root (review code before running).

### First Login & Basic Configuration

After logging in as admin:

1. Go to **App Settings** (`app_settings.php` in the sidebar under Administration).
2. Set **Session Lockout Time** (recommended: 15–60 minutes for shop floor).
3. Configure global theme defaults if desired (Theme Lab).
4. Add **Workshops** and **Production Lines** (very important for asset organization).
5. Add **Departments** (used for purchase order budgeting).

## User Management

### Creating Users

Go to **Users** (under People in the sidebar).

- Click to add a new user.
- Assign a **Role Level**:
  - 1 = Operator (basic ticket logging)
  - 2 = Technician (takeover, log actions)
  - 3 = Supervisor (approvals, work orders, reports)
  - 4 = Admin (full system access)

- Fine-tune permissions using the permission grid if the role defaults are not sufficient.

### Password Management

- Users can change their own password in My Profile.
- Admins can reset passwords for other users via the Users management page.

**Recommendation**: Force password change on first login for new users.

### Roles & Permissions

Permissions are stored in two places:
1. `role_definitions` table (defaults per role level)
2. Per-user `permissions_json` overrides

You can edit role presets in the database or through the Users interface (advanced).

Common permissions include:
- `view_tickets`, `create_tickets`, `takeover_tickets`, `closeout_tickets`
- `view_work_orders`, `manage_work_orders`
- `view_equipment`, `manage_equipment`
- `view_inventory`, `manage_inventory`
- `view_vendors`, `manage_vendors`
- `view_purchase_requests`, `create_purchase_requests`, `approve_purchase_orders`
- `manage_users`, `manage_settings`
- `view_statistics`, `view_history`

## Asset & Production Structure

### Workshops and Production Lines

This is one of the most important setups for shop floor visibility.

1. Go to **Admin Panel** or **App Settings**.
2. Create Workshops (plants/areas).
3. Create Production Lines under each workshop.
4. Assign equipment to lines when creating/editing assets.

This hierarchy appears when registering tickets and in many reports.

### Equipment Master

Use **Equipment** (Assets section) or the **Equipment Vault** (in admin area) to:
- Add new machines and sub-assets.
- Link to production lines.
- Set PM intervals, criticality, warranty info, etc.
- Manage Bill of Materials (BOM) for spare parts.

## Inventory Administration

### Setting Reorder Thresholds

For each part in Inventory:
- Set **Minimum Threshold**
- Set **Maximum Stock** (optional target)
- Set lead times and costs

The system uses these values to flag low stock and support purchasing decisions.

### Viewing the Inventory Ledger

Every part movement (consumption during closeout, receipt via PO) is recorded in the ledger. This is the source of truth for stock levels.

## Purchasing Administration

### Purchase Request Workflow

1. Users create Purchase Requests (PRs).
2. Supervisors review in **Purchase Requests**.
3. Approved PRs can be turned into Purchase Orders (POs).
4. POs are sent to vendors and tracked through multiple statuses.
5. Upon receipt, inventory and the ledger are updated automatically.

### Vendor Management

Maintain the vendor master in **Vendors**.

Include:
- Contact details
- Payment terms
- Lead times
- Performance rating

## Reports & Analytics

### Statistics Page

Available to users with `view_statistics` permission.

Key views:
- Ticket and work order status breakdowns
- Parts consumption over time
- Technician workload
- MTTR / downtime trends

### Audit Log

Admins can view the full audit trail of changes (who changed what and when) via the API or direct queries on the `audit_log` table.

For now, the audit log is primarily consumed programmatically or via direct database access.

## Theming & Branding

### Global Theme Settings

In **App Settings** → Theme Lab:
- Customize the main color tokens for dark and light modes.
- Preview changes live.
- Save as global defaults.

### Per-User Theming

Users can override colors in their **My Profile**.

These preferences are stored server-side and loaded on login.

## Security & Sessions

### Session Lockout

Configured in App Settings.

Recommended values:
- Shop floor / high-turnover areas: 15–30 minutes
- Office / supervisor use: 60–120 minutes

### User Status

Users can be set to:
- Active
- Inactive
- Pending (new accounts awaiting approval)

Deactivate users instead of deleting them to preserve history.

## Backup & Maintenance

See the separate section on **Backup Functionality** (to be implemented / explained separately).

Recommended regular tasks:
- Run database backups (see backup feature once enabled).
- Review and clean old closed tickets if database size becomes an issue.
- Keep an eye on the inventory ledger size.

## REST API for Administrators

The full REST API is available at `/api/v1/`.

Useful for:
- Integrating with other systems
- Building custom dashboards
- Mobile apps
- Automated reporting

See `rest_api_core.md` for the complete reference.

Admin-level API keys can be generated via the `/api-keys` endpoint (requires `manage_users` permission).

## Common Administrative Tasks

- Adding new equipment or production lines before technicians need them.
- Setting up recurring PM schedules in the calendar.
- Reviewing consumption reports to adjust min/max stock levels.
- Managing user access when people change roles or leave.
- Exporting data for external reporting (use the API or direct queries for now).

## Troubleshooting Tips

- **Users can't see certain menu items**: Check their role level and specific permissions.
- **Stock levels not updating**: Make sure consumption is logged during closeout or work order completion.
- **Theme not applying**: Clear browser cache or check that the user has saved preferences.
- **Overdue PMs not showing**: Verify the `scheduled_date` on work orders and that the status is still "Scheduled" or "In Progress".

For deeper technical issues, refer to the AI context documentation in `_ai_ctxt/`.

---

Keep this system practical. The goal is to support the people keeping the machines running, not to create extra administrative work.
